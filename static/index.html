Help · field guide

Everything this dashboard means,
in plain words.

Eighteen short answers, grouped the way you'll need them. Click a question to open its answer - nothing here is marketing, it's exactly what the data is and how to get at it.

Start here

A live, evidence-backed tracker of MCP integration readiness for 100 curated applications. For each app it answers: is there an MCP server, is it vendor-official or community, what can it actually do, how adopted and maintained is it, and is its site up - with every figure linked to the real source that produced it.

The Model Context Protocol: an open standard that lets AI agents call a product's capabilities as tools. An MCP server exposes tools (actions), resources (data) and prompts (templates) over a JSON-RPC stream. This site measures how ready each product is for that world.

Every panel carries its own timestamp ("updated X ago"). The backend refreshes on a schedule (15 minutes by default, plus a 6-hourly cron that commits fresh data), the browser picks up a new refresh within seconds, and the Trends section graphs every refresh snapshot as a point in time.

Reading the data

Official means the registry server's reverse-domain namespace resolves to the app's own domain (com.stripe/mcp to stripe.com) - domain-verified, not claimed. Community means a third-party server whose name/title/description genuinely mentions the app. None means the official MCP registry returned nothing for it - a registry coverage gap, not proof no server exists.

A transparent 0-100 weighted sum of six live signals: official MCP 28%, live capability 14%, adoption 16%, popularity 14%, maintenance 16%, availability 12%. Grades run A-E. Open any app and the Signal breakdown shows each component's exact contribution and its evidence.

Live tools are counted only from a real handshake with the server's endpoint (initialize then tools/list). Auth gated means the endpoint demanded credentials (401/402/403) - that is an auth wall, not zero capability, and we say so instead of guessing a number.

Some endpoints are shared aggregators serving the same toolset to many apps. When one toolset appears behind four or more apps we flag it as a generic gateway and exclude it from app-specific tool counts, so a 41-tool gateway is never credited to every app it wraps.

Downloads are npm/PyPI monthly downloads of the server's published package. Stars are GitHub stars of the repository the registry publishes for that server. Liveness is a direct HTTP check of the app's own site: the status code, latency and whether it responded.

Using the tools

Press Ctrl/Cmd+K (or use the hero search). Curated matches appear instantly; as you type, the live MCP registry is queried for apps beyond the 100, and the Anywhere row fetches any application on the spot with a staged progress card.

Hover a row and press + (up to four apps), then Compare. The deck shows readiness, status, servers, tools, downloads, stars, last commit, license and site side by side, starring the best value per metric. The grid grows a column per app - no empty slots.

A historical diff: what changed between two stored snapshots - tools added/removed/modified, schema and required-parameter changes, auth or protocol changes, endpoints, health - each rated as a potential breaking change (high/medium/low/info). You can pick any two snapshots to compare, and the timeline summarises day by day.

It runs a 12-check behavioural test against a server endpoint (reachable, TLS, handshake, protocol, capabilities, tools/resources/prompts, schema validity, JSON-RPC validity, error handling, auth) and scores it. It is a compatibility report from this explorer's point of view - explicitly not an official certification.

Open an app and press Watch. When a refresh detects that it shipped an official MCP, went down, or changed, an alert fires to the bell, streams over the live wire, and can POST to a webhook (ALERT_WEBHOOK_URL) for Slack/Discord/Zapier.

Explorer is the full filterable, sortable table of every tracked app. Leaderboard ranks them by readiness score. Opportunities lists the apps with real demand - stars, downloads, community servers - but no vendor-official MCP yet: the build candidates. Category, status and grade filters apply to all three.

Yes: the export menu downloads CSV or JSON of the whole dataset, every figure is also served by a plain REST API (see the README), and the explorer itself runs as an MCP server (python -m src.mcp_server) so agents can query it directly.

Honesty & limits

Because "none" means none in the official MCP registry. Verified examples: GitHub ships github/github-mcp-server and Netlify ships netlify/netlify-mcp, yet neither is published in the registry, so both read as community/none here. Read "none" as "not discoverable in the registry".

Registry search is keyword-based and its result set shifts, so aggregate counts wobble by a few percent. A domain-verified official server is protected by an anti-flap rule: one blank cycle marks it "carried over", two in a row accept the removal. The trend chart is direction, not precision.

No. If a source returns nothing we show none; if a fetch fails we show unknown or auth-gated; every card names its source and every number rolls from the figure it replaced. The Methodology window lists all seven pipeline stages with their weights.
